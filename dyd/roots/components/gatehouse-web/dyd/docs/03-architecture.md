# 3. UI architecture

[Documentation index](index.md)

## Presentation boundary

Application pages compose the public API in `src/ui/`. UI components include
controls, typography, navigation, content containers, and layout primitives.
Pages have no presentation HTML, class strings, inline styles, `<style>` blocks,
or direct imports from Bits UI, Lucide, or the shadcn implementation directory.

Existing route/page modules and shared input-form controllers retain application
behavior. They compose the same UI API; they do not define a second component
library. Navigation data and authentication/rename operations are in
`src/app/navigation.ts`, separate from the generic navigation components.

## Components and styling

`src/lib/vendor/shadcn/` contains components generated by shadcn-svelte CLI 1.7.0
using the Nova style. The UI API re-exports components where possible and uses
thin adapters for routing, bindable DOM references, imperative dialog handles,
and generic layout. Additional Tailwind utilities are confined to these adapters.
There are no handwritten component CSS rules.

`AdminContent` and `PageBody` use the full available content width for collections,
details, forms, and hubs. They have no narrow form/detail width presets.

Fullscreen dialog and sheet overlays retain the stock tint without backdrop
blur. Blur would make every input repaint reprocess the page behind the modal.

[Bits UI reference](bits-ui.md) supplies third-party component documentation.

## Navigation links

`RouterLink` renders application destinations as anchors, including button-styled
links through its visual variants. It intercepts ordinary same-tab clicks for
application routing and leaves modified clicks, downloads, external destinations,
and other targets to the browser. Its `replace` option preserves replacement
history where needed. The optional `onNavigate` callback runs only for intercepted
navigation, so opening another tab does not clear a draft or dismiss the current
view.

`Link` supplies native links for destinations outside the application router,
including the standalone file picker. Disabled links expose their disabled state,
have no destination or keyboard stop, and suppress activation. `PaginationFooter`
accepts destination URLs for link-based pagination as well as callbacks for local
collection operations. Buttons perform operations such as creation, submission,
deletion, retry, and local dialog dismissal; successful operations may navigate
afterward.

## Resource ownership and transport

Each resource retains its own API and data model. No generic catalog,
cross-resource search, or generic resource entity API is introduced.

Global directory APIs support a paginated response when `limit` is supplied;
existing unpaginated callers retain their response shape. Native array
collection endpoints retain their body shape. Supplying `limit` opts into bounded
search; `X-Next-Cursor` supplies continuation when available. Records retain
their existing `records`/`values` bodies and `next_cursor` fields.

Workspace pages fetch only their own metadata for named breadcrumbs.
Resource-specific pickers own their API requests. Selected references are
hydrated by ID; candidate collections load only when a selector opens or the
user searches/paginates. Closing aborts pending search requests.

Resource route owners retain their request, pagination, mutation, and refresh
behavior. `ResourcePage` renders their full-page shell or explicitly configured
resource dialog. Opening and closing establish and release the selected
resource's request ownership and subscriptions. `SessionWorkspace` keeps the
conversation mounted while selecting the resource and its displayed route. See
[Lifecycle](04-lifecycle.md) for ownership and state-retention rules.

### Dialog composition

The resource owner supplies `ResourceDialogOptions`: title, search and footer
snippets, view/page keys, pending state, and dismissal callback. It has the data
needed to choose reader titles and editor actions. `SessionWorkspace` supplies
only open/dismiss/close-completion controls and the explicit displayed route.
Dialog configuration flows down through props; children do not register or
override a parent's title, actions, search, or dismissal through context/effects.
`ResourceArticle`, `ResourceActions`, and `FormActions` only render their content.

Search, readers, and editors are successive views in the resource's dialog.
`sessionToolDismissPath` defines their parent destinations and is shared by Cancel
links and shell dismissal. Removal is a separate nested `ResourceRemoval` dialog,
owned by the route that captures its target and performs the mutation. The reader
stays mounted, its dismissal is disabled while the child is active, and the child
dialog's focus scope handles initial Cancel focus and restoration to the trigger.
`SessionSecretsRoute` owns its secret controller and confirmation; its page
component receives the controller and action snippet explicitly.

Capability-based file tools retain their capability transport and shared-draft
completion behavior; their presentation is described in
[Patterns](02-patterns.md#capability-based-file-tools).

## Theming

`src/app.css` uses the supplied shadcn-generated default light/dark palette and
standard Tailwind mappings. No application-specific CSS variables are defined.
Typography for rendered Markdown uses Tailwind's typography plugin.

`Theme` applies the active workspace theme to the document root, including
portaled dialogs and menus. The default follows the system color scheme.
`setWorkspaceTheme(workspaceID, theme)` accepts light/dark values for documented
shadcn tokens and an optional mode. Switching workspaces clears previous
overrides; system/access pages use the default. No workspace overrides are seeded.

### Future extension point

A future branding configuration loader can supply workspace theme data through
this API.

## Architecture checks

The AST-based
[`src/ui/architecture.test.ts`](../assets~output=source/src/ui/architecture.test.ts)
checks the presentation boundary for every page, the access gate, the application
entry point, and the standalone file picker. It also checks the absence of
component `<style>` blocks and the exclusion of generated dependencies and
outputs from source preservation.
